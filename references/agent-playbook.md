# 多 Agent 协作手册

当任务复杂、用户要求高质量成品时，可以把制作流程拆成几个角色。即使当前环境没有真正的 sub-agent，也应按这些角色进行自检。

## 角色分工

| 角色 | 核心任务 | 产出 |
|---|---|---|
| 论文理解 Agent | 阅读 LaTeX，梳理研究逻辑、数据、方法、实验和结论 | 论文摘要、素材目录、关键图表清单 |
| 内容策划 Agent | 设计 10 分钟答辩叙事和页级大纲 | 页码、标题、版式、讲述目的、图源 |
| 模板/美工 Agent | 分析 PPTX 模板，确定网格、颜色、字体、标题栏、页脚 | 模板风格摘要、版式常量 |
| 生成 Agent | 根据大纲和模板生成可编辑 PPTX | 初版 PPTX |
| 文案精修 Agent | 改写标签化内容，补充结果到结论的解释 | 精炼学术段落、高亮重点 |
| QA 审核 Agent | 跑脚本、看预览、检查对齐、留白、字号、重叠 | 问题清单和修复建议 |

## 推荐执行顺序

1. 论文理解 Agent 先完成论文逻辑和图表目录。
2. 内容策划 Agent 根据答辩时长生成页级大纲。
3. 模板/美工 Agent 运行 `scripts/analyze_template.py`，确定模板风格。
4. 生成 Agent 生成 PPTX。
5. 文案精修 Agent 检查所有页面，特别是实验结果页。
6. QA 审核 Agent 运行结构 QA、预览导出和视觉 QA。
7. 生成 Agent 根据 QA 结果修复，再由 QA 审核 Agent 复查。

## 交接信息

每个角色交接时尽量使用结构化摘要：

```text
研究主线：
数据与标的：
核心方法：
必须展示的图：
可选图：
目标页数：
模板风格：
高风险页面：
```

## 审核重点

QA 审核 Agent 应特别关注：

- 封面和致谢页是否中心轴对齐。
- 目录页是否有视觉层次，不是普通列表。
- 数据页是否讲清来源、频率、时间范围和研究标的。
- 方法不足页是否表达为“任务困难 -> 既有不足 -> 本文响应”，不要说本文模型有主要不足。
- 实验页是否写清每个结果证明的结论。
- 图片框、文本框、分析卡、结论条是否按统一边界对齐。
- 大卡片是否存在明显空白。
- 同级文本字号是否一致。
- 生成图中文字是否正确。

## 修复决策

| QA 发现 | 优先修复方式 |
|---|---|
| 图文重叠 | 重新分栏或缩放图片框，必要时拆页 |
| 页面太空 | 缩小卡片、补证据小卡或改为更大图版式 |
| 文字太浅 | 补充“结果 -> 结论”段落，而不是增加关键词 |
| 字号漂移 | 统一角色字号常量后批量修复 |
| 封面偏移 | 所有核心元素回到中心轴 |
| 模板不像 | 重新提取主色、标题栏、页脚和 logo 位置 |

## 最终交付标准

只有当以下条件满足时才交付：

- 大纲和论文逻辑一致。
- 关键论文图已复用。
- 结构 QA 无硬错误。
- 已生成并查看预览图或 contact sheet。
- 视觉 QA 警告已人工判断或修复。
- 对用户明确说明输出路径、页数、QA 结果和残留风险。
